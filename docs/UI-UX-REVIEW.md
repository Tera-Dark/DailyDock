# DailyDock UI/UX 精细化评审

参考标准：`Tera-Dark/personal-agent-skills/02_design/chatgpt-inspired-ui/SKILL.md`、`references/design-tokens.md`、`references/review-checklist.md`。

## Brief

- 类型：本地浏览器签到/待办工具
- 主任务：打开浏览器弹窗→查看今日未完成→访问签到网址→主动标记完成
- 次任务：创建和修改周期、定时提醒、备份
- 页面：392px 工具栏弹窗；独立扩展管理页
- 最低目标：不增加网络/账号/框架，保留 v0.1 旧数据和提醒逻辑

## 实施后的信息架构

| 页面 | 第一优先 | 第二优先 | 隐藏到二级 |
|---|---|---|---|
| Popup | 今日待办列表、完成、打开网站 | 回车快捷新增 | 完整编辑、导入导出 |
| 今天 | 今日进度、任务列表、快捷新增 | 搜索与状态过滤 | 编辑表单 |
| 全部任务 | 全量任务扫描及状态 | 添加、编辑、删除 | 设置 |
| 网站签到 | 仅显示带网址任务 | 打开网站、勾选完成 | 自动签到（不做） |
| 偏好与数据 | 主题、导出/导入 | 数据安全提示 | 无 |

## 已识别问题与修正

| 等级 | 原始问题 | 用户影响 | 实施 |
|---|---|---|---|
| P1 | 任务编辑表单长期占据页面 | 浏览清单需要跳过较大表单 | 改原生 dialog，按需打开 |
| P1 | 所有分组大量卡片与绿色状态装饰 | 信息流断裂、注意力分散 | 中性语义 token、细分割线、行列表 |
| P1 | 仅今日视图，无全量/网站任务分组 | 未来任务不容易发现 | 增加导航和搜索 |
| P1 | 没有主题/键盘焦点明确策略 | 深色系统与键盘操作体验差 | 系统/浅/深色、focus-visible、语义标签 |
| P1 | 提醒缺少状态入口、稍后提醒 | 日常使用可能遗漏 | 工具栏 badge + 通知中延后 10 分钟 |
| P2 | 保存/导入缺少统一反馈 | 不确定是否成功 | 统一 aria-live 状态提示 |
| P2 | 重复任务表单默认暴露所有选项 | 新任务创建负担高 | 快捷新增 + 低频规则收进 Dialog |

## 状态与无障碍

- 主要控制均有文字或 `aria-label`；原生 `dialog` 支持 Esc 关闭和焦点管理。
- 全局语义 token 包括 background、surface、text、muted、border、accent、focus、success、danger。
- `:focus-visible` 对键盘可见；`prefers-reduced-motion` 关闭动画；窄屏表单回退单列。
- 未实现自动标记签到成功，网站打开仅负责导航。
- 不访问网络，不发送任何任务或隐私内容，不依赖第三方组件。

## 已知边界

- 当前所谓“网页”是扩展内置 options 页面，而不是独立的 GitHub Pages 网站；因此弹窗和管理页天然共享同一份 `chrome.storage.local`。
- 电脑/浏览器关闭时不保证定时通知；重要事项请同时使用系统日历或闹钟。
- `chrome.storage.local` 并不是加密保险箱，不应添加密码、Cookie 或 API Key。
- 目前没有云同步，也没有自动登录签到网站。

## 手工回归清单

1. 新安装 → 空状态 → 添加每日任务 → 弹窗显示和角标更新。
2. 编辑为每周指定星期并启用提醒；检查当天调度、次日重复。
3. 单次任务完成、刷新、修改日期、重复打开后状态正确。
4. 新增带网址任务 → 「网站签到」出现 → 只打开 http/https → 不自动勾选。
5. 删除任务需要确认，编辑保存/导入有反馈。
6. 导出 JSON → 删除任务 → 导入备份后任务/完成记录恢复。
7. 系统深浅色变化、手动切换与键盘 Tab/Esc。
8. 缩放、长标题、较多任务及狭窄屏宽无横向溢出。
